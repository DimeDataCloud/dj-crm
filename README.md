# dj-crm (Booking OS)

A booking CRM and club lead generator for an artist manager. It finds nightclubs, dance halls and music bars in the New York and New Jersey metro, tracks every venue through a booking pipeline, and handles calendar, money and follow-up automation. Desktop-first, usable on a phone, installable as a home-screen app.

## Features

- **Tonight:** next show, open tasks generated by automation, hot contactable leads, funnel and a live activity feed.
- **Venues:** every venue with contact details, filters by stage, area and contactability, CSV export.
- **Lead generator:** sweeps OpenStreetMap for venues across 13 areas, then reads each venue's own public website (home, contact, booking and private-events pages) for booking emails, phone numbers and social links. It does not invent contacts: unreadable sites are flagged as unassessed.
- **Pipeline:** drag-and-drop board across nine stages (long-press on mobile).
- **Calendar:** month grid and agenda view for holds, confirmations, played and cancelled dates.
- **Analytics:** 3D map of the territory with each venue plotted at its coordinates, coloured by stage and sized by capacity, lead score or revenue.
- **Financials:** booked, collected and outstanding amounts, deposits owed, expenses, net, per-venue revenue and unit economics.
- **Workflow:** six editable automation rules and message templates with merge fields. Rules run server-side every 15 minutes.
- **Artist profile:** bio, streaming links, embeddable player and a copy-paste press kit.

Automation only creates tasks. Nothing sends email or messages on its own. Composing an email opens the user's own mail client with the draft filled in.

## Tech stack

- Node.js 22 or later (Docker image uses Node 24), using the built-in `node:http` and `node:sqlite` modules
- SQLite through `node:sqlite`, with no native build step
- Vanilla ES-module frontend, no build step
- Three.js vendored locally for the 3D map
- Docker image based on `node:24-alpine`

## Quick start

Requires Node.js 22 or later.

```bash
cd dj-crm
cp .env.example .env
```

Edit `.env` and set `SESSION_SECRET`, `ADMIN_PASSWORD` and `ADMIN2_PASSWORD`. A random secret can be generated with:

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

No installation step is needed (there are no runtime dependencies). Start the server:

```bash
npm start
```

Open http://localhost:3007 and sign in with `ADMIN_EMAIL` or `ADMIN2_EMAIL` and the matching password. For plain-http local use, set `INSECURE_COOKIE=1` in `.env`.

### Docker

```bash
docker build -t dj-crm .
docker run --env-file .env -p 3007:3007 -v dj-data:/app/data dj-crm
```

## Configuration

| Variable | Required | Default | Description |
|---|---|---|---|
| `SESSION_SECRET` | Yes | none | Key used to sign session cookies. Use a long random value. |
| `ADMIN_PASSWORD` | Yes | none | Password for the first manager account. |
| `ADMIN2_PASSWORD` | Yes | none | Password for the second account. |
| `ADMIN_EMAIL` | No | `manager@example.com` | Login email for the first manager account. |
| `ADMIN2_EMAIL` | No | `get@dimedata.cloud` | Login email for the second account. |
| `PORT` | No | `3007` | HTTP port. |
| `DB_PATH` | No | `data/djcrm.db` | SQLite database file. |
| `AUTOMATION_INTERVAL_MIN` | No | `15` | Minutes between automation runs. |
| `INSECURE_COOKIE` | No | unset | Set to `1` only for plain-http local development. |

The two accounts are created only when the `users` table is empty, on first boot. The artist profile is seeded with placeholder values and is edited in the app.

## Maintenance scripts

Run inside the project directory (or inside the container with `docker exec`):

```bash
node server/discover-cli.js --enrich 150    # offline sweep, writes data/seed-venues.json
node server/clean-contacts.js --reenrich 60 # rescrub contacts, re-read venue sites, rescore
node server/prune-nonvenues.js              # archive dance schools and studios that slipped in
```

Lead generation reads public OpenStreetMap data and venue websites. Respect the providers' rate limits and terms, and check any contact details before use.
